## 1. Быстрый старт

### Требования

| Инструмент | Версия | Описание |
|-----------|--------|----------|
| Docker Desktop | 24+ | Для запуска всех сервисов |
| Node.js | 18+ | Только для локальной разработки |
| Python | 3.11+ | Только для локальной разработки |
| PostgreSQL | 15+ | Только для локальной разработки |

### Один командой (Docker)

```bash
git clone https://github.com/AidarValievRin/aivinity-tasks.git
cd aivinity-tasks/taskmanager
docker-compose up --build
```

Открой браузер: **http://localhost:3000**

## 2. Локальный запуск без Docker

### Шаг 1 — База данных

Установи PostgreSQL и создай базу данных:

```sql
CREATE DATABASE taskmanager;
CREATE USER taskuser WITH PASSWORD 'taskpass';
GRANT ALL PRIVILEGES ON DATABASE taskmanager TO taskuser;
```

### Шаг 2 — Backend

```bash
cd taskmanager/backend

# Установить зависимости
npm install

# Создать .env файл
cp .env.example .env
```

Отредактируй `backend/.env`:

```env
DATABASE_URL="postgresql://taskuser:taskpass@localhost:5432/taskmanager"
JWT_SECRET="замените-на-свой-секретный-ключ-не-менее-32-символов"
JWT_REFRESH_SECRET="замените-на-другой-секретный-ключ"
PORT=3001
NODE_ENV=development
```

```bash
# Применить схему базы данных
npx prisma db push

# Запустить сервер
npm run dev
```

Backend запустится на **http://localhost:3001**

### Шаг 3 — Frontend

Открой новый терминал:

```bash
cd taskmanager/frontend

# Установить зависимости
npm install

# Запустить dev-сервер
npm run dev
```

Frontend запустится на **http://localhost:5173**

### Шаг 4 — Telegram-бот

Открой ещё один терминал:

```bash
cd taskmanager/bot

# Установить зависимости
pip install -r requirements.txt

# Создать .env файл
cp .env.example .env
```

Отредактируй `bot/.env`:

```env
BOT_TOKEN=7639602148:AAGk9tDQrWE9VgbRgMTO6f0fRp03csAnNpo
API_URL=http://localhost:3001
```

```bash
# Запустить бота
python main.py
```

## 3. Запуск через Docker

### Продакшн

```bash
cd taskmanager
docker-compose up --build -d
```

Сервисы:
- **Веб-панель:** http://localhost:3000
- **API:** http://localhost:3001
- **База данных:** localhost:5432

### Остановка

```bash
docker-compose down
```

### Остановка с удалением данных

```bash
docker-compose down -v
```

### Режим разработки с hot-reload

```bash
docker-compose -f docker-compose.dev.yml up --build
```

### Просмотр логов

```bash
# Все сервисы
docker-compose logs -f

# Только бот
docker-compose logs -f bot

# Только backend
docker-compose logs -f backend
```

## 4. Регистрация и вход

### Регистрация

1. Открой http://localhost:3000
2. Нажми **"Регистрация"**
3. Заполни поля:
   - **Имя пользователя** — уникальный логин (латиница, цифры, `_`)
   - **Email** — электронная почта
   - **Пароль** — минимум 6 символов
4. Нажми **"Зарегистрироваться"**

После регистрации тебе автоматически присваивается **уникальный код** вида `AIV-XXXX`.
Этот код нужен для:
- Приглашения в командные задачи
- Привязки Telegram-аккаунта

### Вход

1. Введи Email и пароль
2. Нажми **"Войти"**

## 5. Мои задачи

### Интерфейс

Страница **"Мои задачи"** состоит из 4 блоков:

#### Статистика (верхняя панель)

| Показатель | Описание |
|-----------|----------|
| Всего | Общее количество задач |
| В работе | Задачи со статусом "В работе" |
| Выполнено | Завершённые задачи |
| Просрочено | Задачи с истёкшим сроком |
| Прогресс % | Выполнено / Всего × 100 |

#### Фильтры и поиск

- **Поиск** — по заголовку и описанию задачи
- **Все** — показать все задачи
- **Высокий приоритет** — только срочные и высокие
- **Активные** — задачи не завершены и не отменены
- **Сегодня** — задачи со сроком на сегодня
- **Просроченные** — просроченные задачи

#### Переключение вида

- **Список** — задачи сгруппированы по статусу (В работе → Ожидают → Выполнено)
- **Канбан** — 3 колонки с перетаскиванием мышью

### Создание личной задачи

1. Нажми кнопку **"+ Создать задачу"** (правый верхний угол)
2. Заполни форму:

| Поле | Описание | Обязательно |
|------|----------|-------------|
| Заголовок | Краткое название задачи | Да |
| Описание | Подробное описание | Нет |
| Категория | Тип задачи (Разработка, Дизайн, и т.д.) | Нет |
| Приоритет | Низкий / Средний / Высокий / Срочно | Да |
| Срок выполнения | Дата дедлайна | Нет |

3. Нажми **"Создать"**

### Приоритеты

| Приоритет | Цвет | Описание |
|-----------|------|----------|
| Низкий | Серый | Несрочные задачи |
| Средний | Синий | Стандартные задачи |
| Высокий | Оранжевый | Важные задачи |
| Срочно | Красный | Требует немедленного внимания |

### Статусы личных задач

| Статус | Описание |
|--------|----------|
| Новая | Задача только создана |
| В работе | Задача выполняется |
| Выполнено | Задача завершена |

### Просмотр и редактирование задачи

Нажми на карточку задачи — откроется детальный вид:
- Изменить заголовок, описание
- Сменить статус через выпадающий список
- Изменить приоритет
- Сменить категорию
- Установить или изменить дату
- Добавить комментарий

### Перетаскивание (Канбан)

В режиме Канбан — зажми карточку задачи и перетащи в нужную колонку:
- **Новые** → **В работе** → **Выполнено**

Статус обновляется автоматически и сохраняется на сервере.

### Добавление категорий

В форме создания задачи нажми **"+ Добавить"** рядом с полем категории, введи название и выбери цвет.

## 6. Командные задачи

### Создание команды

1. Перейди на вкладку **"Командные задачи"**
2. Нажми **"+ Создать команду"**
3. Введи название команды
4. Нажми **"Создать"**

### Приглашение участников

Участников приглашают **по уникальному коду** `AIV-XXXX`.
Это сделано намеренно — ты видишь только тех, кого лично пригласил.

1. Нажми на команду → **"Настройки команды"**
2. В поле **"Пригласить по коду"** введи код участника (например, `AIV-K3T7`)
3. Нажми **"Пригласить"**

Участник должен сообщить тебе свой код из своего профиля (раздел **Профиль → Мой код**).

### Интерфейс командных задач

Канбан-доска с 5 колонками:

| Колонка | Статус | Описание |
|---------|--------|----------|
| Новые | `new` | Только созданные задачи |
| Выполняются | `in_progress` | В работе |
| Приостановлены | `on_hold` | Временно остановлены |
| Зависшие | `stuck` | Требуют внимания |
| Отменены | `cancelled` | Отменённые задачи |

### Создание командной задачи

**Способ 1 — кнопка в колонке:**
1. В любой колонке нажми **"+ Добавить"**
2. Задача автоматически получит статус этой колонки

**Способ 2 — общая кнопка:**
1. Нажми **"+ Создать задачу"** в правом верхнем углу
2. Выбери нужный статус в форме

### Поля командной задачи

| Поле | Описание | Обязательно |
|------|----------|-------------|
| Заголовок | Краткое название | Да |
| Описание | Подробное описание | Нет |
| Статус | Колонка канбана | Да |
| Приоритет | Низкий / Средний / Высокий / Срочно | Да |
| Категория | Тип работы | Нет |
| Ответственный | Кто выполняет | Нет |
| Наблюдатели | Кто следит | Нет |
| Срок выполнения | Дедлайн | Нет |

### Детали командной задачи

Нажми на карточку — откроется панель справа:
- Редактировать все поля
- Назначить/сменить ответственного
- Добавить/убрать наблюдателей
- Написать комментарий
- Сменить статус через dropdown или перетаскивание
- Сдвинуть дедлайн через календарь

### Уведомления

При назначении задачи ответственному — если он привязал Telegram, ему придёт уведомление в бот.

### Перетаскивание

Зажми карточку задачи и перетащи в другую колонку. Статус обновится автоматически.

## 7. Профиль и Telegram

### Просмотр профиля

Нажми на аватар в правом верхнем углу → **"Профиль"**

На странице профиля:
- **Имя пользователя** и Email
- **Уникальный код** `AIV-XXXX` (можно скопировать кнопкой)
- Дата регистрации
- Раздел привязки Telegram

### Как узнать свой Telegram ID

1. В Telegram открой бота **@userinfobot**
2. Отправь любое сообщение
3. Бот вернёт твой числовой ID (например: `123456789`)

### Привязка Telegram к профилю

**Способ 1 — через веб-панель:**
1. На странице Профиль введи свой Telegram ID в поле
2. Нажми **"Привязать"**

**Способ 2 — через Telegram-бота:**
1. Открой бота в Telegram: `@твой_бот`
2. Отправь команду `/link`
3. Введи свой уникальный код `AIV-XXXX`
4. Получи подтверждение: "Аккаунт успешно привязан!"

После привязки ты сможешь:
- Создавать задачи через бота
- Получать уведомления о назначении на командные задачи

## 9. Переменные окружения

### Backend (`backend/.env`)

```env
# База данных
DATABASE_URL="postgresql://user:password@host:5432/dbname"

# JWT (обязательно менять в продакшне!)
JWT_SECRET="минимум-32-символа-случайная-строка"
JWT_REFRESH_SECRET="другая-минимум-32-символа-строка"

# Сервер
PORT=3001
NODE_ENV=development

# Frontend URL (для CORS)
FRONTEND_URL=http://localhost:5173
```

### Bot (`bot/.env`)

```env
BOT_TOKEN=7639602148:AAGk9tDQrWE9VgbRgMTO6f0fRp03csAnNpo
API_URL=http://localhost:3001
```

### Frontend (`.env` или `vite.config.js`)

Для продакшна измени URL бэкенда в `frontend/vite.config.js`:

```js
server: {
  proxy: {
    '/api': 'http://localhost:3001',
    '/socket.io': 'http://localhost:3001',
  }
}
```

### База данных

```
User ←──── TeamMember ────→ Team
  |                           |
  |                           |
  └──→ Task (личная)         └──→ Task (командная)
         |                              |
         └──→ Comment          watchers: User[]
```

### Поток авторизации

```
Регистрация → JWT access (15 мин) + refresh (7 дней, httpOnly cookie)
             → При истечении access — автоматический refresh через interceptor
             → При истечении refresh — редирект на /login
```

### Real-time обновления

```
Любое изменение задачи → Backend emit Socket.io event
                       → Frontend listener обновляет Zustand store
                       → React ре-рендерит компоненты
```

## 11. Масштабирование

### Горизонтальное масштабирование backend

Backend stateless — можно запускать несколько инстансов:

```yaml
# docker-compose.yml
backend:
  deploy:
    replicas: 3
```

Для Socket.io при нескольких инстансах нужен Redis адаптер:

```bash
npm install @socket.io/redis-adapter ioredis
```

### Переход на managed PostgreSQL

Замени `DATABASE_URL` в `.env` на строку подключения к облачной БД (Supabase, Neon, Railway).

### Добавление Redis для сессий

Для продакшна рекомендуется хранить refresh-токены в Redis:

```bash
npm install ioredis
```

### Мониторинг

Endpoint для health-check уже есть: `GET /api/health`

Можно подключить:
- **Prometheus + Grafana** — метрики
- **Sentry** — трекинг ошибок

### CI/CD

Пример GitHub Actions (`.github/workflows/deploy.yml`):

```yaml
on:
  push:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Deploy via SSH
        run: |
          ssh user@server "cd /app && git pull && docker-compose up -d --build"
```

## Часто задаваемые вопросы

**Q: Как найти свой уникальный код?**
A: Профиль (аватар в правом верхнем углу) → раздел "Мой код". Нажми кнопку копирования.

**Q: Бот не отвечает на /tasks?**
A: Убедись что аккаунт привязан через `/link`. Без привязки бот не знает, чей аккаунт.

**Q: Задача создана в боте, но не появилась на сайте?**
A: Проверь что backend запущен (`http://localhost:3001/api/health`). В `bot/.env` должен быть правильный `API_URL`.

**Q: Не приходит уведомление об назначении?**
A: Ответственный должен привязать свой Telegram. Проверь в его профиле.

**Q: Как добавить свою категорию задач?**
A: В форме создания задачи нажми "+ Добавить" рядом с полем категории.

**Q: Как удалить участника из команды?**
A: Команда → Настройки → рядом с участником нажми иконку удаления.
